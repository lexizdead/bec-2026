# Прошивка «Швидкісний кабель-укладач»

Arduino Nano · L298N · 2 мотори TT (передній привід) · TCRT5000 лінії (по краю смужки) · TCRT5000 міток (40 мм збоку) · SG90 револьверного магазину · 2 енкодери LM393 (HC-020K).

```
firmware/
├── Makefile                 збірка/заливка через arduino-cli
├── README.md                цей файл
└── kabel_ukladach/          скетч (назва папки = назва .ino, так вимагає Arduino)
    ├── kabel_ukladach.ino   автомат станів, PID, мітки, скидання, Serial-меню
    ├── config.h             УСІ піни й параметри
    ├── motors.*             L298N: швидкість, гальмо
    ├── sensors.*            TCRT5000: нормалізація 0–1000, калібрування
    ├── odometry.*           енкодери на перериваннях D2/D3 → мм
    ├── magazine.*           SG90: плавний поворот барабана на наступну камеру
    └── settings.*           калібрування й PID в EEPROM
```

## ⚠ Зміна пінів відносно схеми Е3
Кнопка «Старт» переїхала з **D2 на D4**, бо лише D2 і D3 на Nano мають апаратні переривання, а вони потрібні енкодерам.

| Що | Пін |
|---|---|
| ENA / IN1 / IN2 (лівий) | D5 / D7 / D8 |
| ENB / IN3 / IN4 (правий) | D6 / D11 / D12 |
| SG90 сигнал | D9 |
| **Кнопка «Старт»** (другий контакт на GND) | **D4** |
| **Енкодер лівий / правий** (DO, живлення +5V_N і GND) | **D2 / D3** |
| TCRT лінії / міток (AO) | A0 / A3 |

Без енкодерів: `ENC_COUNT 0` у `config.h` — робот доїжджає від мітки до точки скидання за часом (`T`).

## Налаштування на Arch (≈10 хв, плата не потрібна)
```bash
sudo pacman -S --needed arduino-cli zip
sudo usermod -aG uucp $USER          # доступ до /dev/ttyUSB0; потім вийти й увійти знову
cd firmware
make setup                            # ядро AVR + Servo
make build                            # має написати «Sketch uses ~16000 bytes»
```
Arduino IDE: відкрийте `kabel_ukladach/kabel_ukladach.ino`, Board → **Arduino Nano**, Processor → **ATmega328P (Old Bootloader)** (для клонів з CH340), Port → `/dev/ttyUSB0`.
VSCodium: розширення **clangd** з Open VSX, потім `make ide` — з'явиться автодоповнення.

Якщо плата не з'являється як `/dev/ttyUSB0`: `sudo dmesg | tail`; якщо встановлено `brltty`, він перехоплює CH340 — `sudo pacman -R brltty`.
Відкриття Serial-монітора перезапускає Nano — це нормально.

## Запуск по кроках (з Serial-монітором, 115200)
Робот на підставці, колеса в повітрі. `h` — список команд.

1. **`p`** — плата жива, друкує налаштування.
2. **`m`** — лівий, правий, обидва вперед. Крутиться назад → `MOTOR_L_INVERT 1` (або поміняти дроти мотора).
3. **`e`** — кожне колесо робить рівно 1 оберт. Ні → перевірте диск, `ENC_SLOTS`, дроти D2/D3.
4. **`v`** кілька разів, потім **`0`** — барабан ходить по камерах. Кути підібрати в `MAG_ANGLES` під реальний барабан.
5. **Калібрування**: датчики над **білим**, натисніть `c` (або ввімкніть живлення з затиснутою кнопкою), за 6 с кілька разів проведіть робота рукою поперек лінії й через мітку. Має бути `OK` для обох.
6. **`s`** — над білим ≈0, над смужкою ≈1000, датчик лінії на краю ≈500. Датчик міток над міткою > 600.

## Підбір на трасі
Команди змінюють значення одразу; **`w`** — зберегти в EEPROM.

| Симптом | Що робити |
|---|---|
| Хитається з боку в бік | `P` менше (P0.18) або `D` більше (D3) |
| Повільно реагує, вилітає на поворотах | `P` більше (P0.35), або `B` менше |
| Пропускає мітки | `Z` менше (повільніше біля мітки), `MARK_THR` у config.h нижче |
| Хибні мітки | `MARK_MIN_SAMPLES` більше |
| Шкант падає **до** мітки на X мм | `O` більше на X |
| Шкант падає **після** мітки на X мм | `O` менше на X |
| Без енкодерів: те саме | `T` більше / менше |

Лог руху: `l`, потім `g` (старт без кнопки). Рядки `t,мм,лінія,мітка,стан`, а також `MARK @…`, `DROP n`, `STOP: …` — видно, де саме спрацювало.

## Як влаштована логіка
- **PID по краю.** Один датчик стоїть над лівим краєм смужки, PID тримає 50 % чорного. Більше чорного → робот з'їхав управо → кермо вліво. Якщо датчик над правим краєм — `LINE_ON_LEFT_EDGE 0`.
- **Мітка = три умови:** датчик міток чорний `MARK_MIN_SAMPLES` циклів поспіль, датчик лінії теж чорний (мітка перетинає лінію), від попередньої мітки ≥ 300 мм. Над міткою кермо тримає згладжений курс, щоб робот не смикнувся.
- **Синхронізація скидання.** Мітка помічена на відстані `d` → робот повільно їде до `d + O` (датчик міток попереду щілини на ~180 мм), гальмує, серво повертає барабан, 0.4 с чекає падіння, рушає далі. Поки робот стоїть, серво не конкурує з моторами за струм.
- **Пропущена мітка** (з енкодером): якщо через 500 + 80 мм мітки не було, шкант скидається там, де вона мала бути.
- **Фініш:** після 9-го шканта робот їде до кінця лінії; лінії немає 80 мм → стоп. Безпека: кнопка під час їзди, втрата лінії на 400 мм до 9-го шканта, 3 хв загалом.

[naufalfarisi/LineFollower-Robot](https://github.com/naufalfarisi/LineFollower-Robot) і
[phurin-git/line-following-robot](https://github.com/phurin-git/line-following-robot); скидання сервоприводом під час руху по лінії — як у
[Feramos19/UGV-Line-Tracking-Detachment-Mechanism](https://github.com/Feramos19/UGV-Line-Tracking-Detachment-Mechanism).
Готового відкритого коду з одним датчиком по краю, окремим датчиком міток і револьверним магазином не знайшлося, тож ці частини написані під ваш робот.
